# Rustプログラミング言語辞書コンテンツ

作成予定の辞書コンテンツを記載する。作成したらチェックを入れること。

## 01-basic

- [x] 変数（`let`による束縛、デフォルトで不変、`mut`による可変化）
- [x] 定数（`const`宣言、型注釈必須、`SCREAMING_SNAKE_CASE`、不変な変数との違い）
- [x] シャドーイング（同名の`let`による覆い隠し、`mut`との違い（型の変更が可能））
- [x] 式（評価されると値を生成する単位、Rustが「式言語」であること、式の代表例）
- [x] 文（宣言文と式文の2分類、セミコロンの働き（値を捨てる））
- [x] プリミティブ型（コンパイラ組み込みの基本型、スカラー型と複合型の大別）
- [x] 整数型（符号の有無とビット幅、既定は`i32`、`isize`/`usize`）
- [x] 浮動小数点型（IEEE 754準拠、`f32`/`f64`、既定は`f64`）
- [x] 論理値型（`true`/`false`の2値、1バイト）
- [x] 文字型（Unicodeスカラー値1つ、常に4バイト固定長、シングルクォート記法）
- [x] ユニット型（唯一の値`()`、「返す値がない」ことの表現、現れる場面）
- [x] タプル型（異なる型を固定個数まとめる、タプルインデックス式とパターンによる分解）
- [x] 配列型（同じ型を固定長で並べる、要素数が型の一部、添字と`get`によるアクセス）
- [x] スライス（列の一部または全体を指すビュー`[T]`、動的サイズ型のため`&[T]`で扱う、境界チェック）
- [x] 文字列スライス（UTF-8の文字列データを表す`str`、動的サイズ型のため`&str`で扱う、参照とスライスの関係）
- [x] 文字列リテラル（ダブルクォート記法、型は`&'static str`、生文字列・バイト文字列・C文字列の派生記法）
- [x] 文字列型（`String`、ヒープにデータを所有し伸長できる、生成・変更方法、`&str`との使い分け）
- [x] ベクタ（Vec）（可変長のコレクション型、ヒープ確保、生成・変更・アクセス方法）
- [x] 数値演算（加減乗除と剰余の5種、整数の除算は0方向への切り捨て、オーバーフローの扱い）
- [x] 論理演算子（AND・OR・NOT、`&&`と`||`の短絡評価）
- [x] キャスト（`as`演算子による明示的な型変換、パニックせず値が黙って変化する点）
- [x] 関数（`fn`による定義、引数の型注釈は必須、戻り値は本体末尾の式）
- [x] return式（実行を打ち切って値を返す、主用途は早期リターン、末尾の式との使い分け）
- [x] if式（条件による分岐、ブロックの値がif式全体の値になる、if let式）
- [x] loop式（無限ループ、`break`で値を返せる唯一のループ、3種のループとの比較）
- [x] while式（条件がtrueの間繰り返す述語ループ、値は常にユニット型、while let式）
- [x] for式（イテレータの要素ごとに繰り返す、コレクションの渡し方3通り（所有・共有参照・排他参照））
- [x] ループラベル（`'名前:`の記法、ネストしたループの対象指定、ブロック式に付けて`break`で値を返す）
- [x] 範囲式（`start..end`と`start..=end`、6つの形式、forの反復とスライスの添字指定）
- [x] コンソール出力（`println!`/`print!`マクロ、`{}`と`{:?}`のフォーマット指定、`#[derive(Debug)]`）
- [x] コメント（`//`の行コメント、`/* */`のブロックコメント、`///`・`//!`のドキュメンテーションコメント）
- [x] スコープ（名前が有効な範囲、ブロックによる区切り、シャドーイング・所有権・借用との関わり）
- [x] 可変性（既定は不変であること、`mut`による可変化、変数の可変性と参照の可変性の区別、束縛の可変性であってデータ自体の性質ではないこと）
- [x] 型推論（型注釈を省略できる仕組み、注釈が必須になる場面（関数の引数・定数など）、整数は`i32`・浮動小数点数は`f64`といった既定型）
- [x] 比較演算子（`==`・`!=`・`<`・`<=`・`>`・`>=`、結果は論理値型、同じ型同士でしか比較できないこと）
- [x] main関数（プログラムのエントリポイント、バイナリクレートに必須、戻り値に`()`と`Result`を取れること）
- [x] マクロ（`!`が付く呼び出し、関数との違い（可変長引数・コンパイル時展開）、宣言的マクロと手続き的マクロの区別。利用側の視点に絞る）
- [x] パニック（回復不能なエラーで実行を中断する仕組み、`panic!`マクロ、境界外アクセスや整数オーバーフローなど暗黙に起きる場面、巻き戻しと中止）
- [x] 静的変数（`static`宣言、プログラム全体の寿命を持つ、定数との違い（実体が1つ・アドレスを持つ）、`static mut`が`unsafe`な理由）
- [x] never型（値を生成せず発散することを表す`!`、どんな型とも互換になる、`return`・`break`・`panic!`・`loop`が持つ型）

## 02-std

- [x] 標準ライブラリ（core・alloc・stdの3クレート構成、それぞれの違いと依存関係、通常「標準ライブラリ」が指すのはstd）
- [x] 変換トレイト（From/IntoとTryFrom/TryInto、失敗しない変換とResultを返す変換、実装はFrom側に書く慣習、浮動小数点数がからむ変換）

## 03-ownership

- [x] 所有権（すべての値にただ1つの所有者、所有権の3つのルール、GCも手動解放も使わずコンパイル時検査でメモリ安全を保証する仕組み、なぜ所有権が必要なのか）
- [x] ムーブ（代入や関数呼び出しでの所有権の移動、ムーブ後の変数は未初期化、ムーブが起きる場面、ムーブしない型（Copy型））
- [x] クローン（`.clone()`による明示的な複製、ヒープのデータごと複製される、Copyとの違い）
- [x] 参照（所有権を移動させずに値を指す`&T`・`&mut T`、共有参照（不変参照）と排他参照（可変参照）の2種類）
- [x] 借用（参照を作って一時的に利用する行為、「共有はいくつでも、可変はただ1つ」の借用規則、借用の継続期間、所有者側の制約）
- [x] 参照外し（単項`*`演算子による参照先へのアクセス、読み書きの両方に使える）
- [x] ダングリング参照（参照先が破棄済みの無効な参照、借用チェッカーがコンパイル時に検出する仕組み）
- [x] NLL（非レキシカルライフタイム）（借用の有効範囲を最後に使われる地点までとする解析方式、Rust 1.31で安定化）
- [x] Copyトレイト（ムーブの代わりにビット単位の複製が起きる目印、実装できる型の条件（`Drop`と排他）、`Clone`との関係と使い分け）
- [x] 借用チェッカー（所有権・借用規則・ライフタイムをコンパイル時に検査する仕組み、代表的なエラー（E0382・E0502・E0499・E0515）、実行時コストがゼロであること）

## 04-struct

- [x] 構造体（構造体の定義方法、構造体へのアクセス、フィールド初期化省略記法、補足：構造体のデバッグ）
- [x] 構造体更新記法（所有権絡みの話も記載）
- [x] 関連関数（関連関数の概念、メソッド、メソッド以外の関連関数の2つに分けられる、メソッド以外の関連関数のことを慣習的に「関連関数」と呼ぶことがあるが、メソッドも関連関数の一つのため注意、ここではメソッド以外の関連関数について記載する）
- [x] メソッド
- [x] implブロック（関連関数、メソッドの両方はimplブロックに定義する、複数のimplブロックに分けられる）
- [x] 自動参照（メソッド呼び出し時の自動参照・参照外しについて）
- [x] タプル構造体
- [x] ユニット様構造体

## 05-enum

- [x] 列挙型（enumの定義方法、バリアント、バリアントへのデータの持たせ方（データなし・タプル的・構造体的）、構造体との違い、implブロックでメソッドも定義できる）
- [x] Option型（標準ライブラリのenum、Rustにnullがない理由とnull安全、Some/Noneバリアント、`Option<T>`と`T`は別の型のため値を使うには取り出しが必要）
- [x] Result型
- [x] match式（制御フロー構文、アームとパターン、値を束縛するパターン、`Option<T>`とのマッチ、網羅性チェック（あり得る場合をすべて処理しないとコンパイルエラー））
- [x] 包括パターン（catch-allパターン、変数名で値を使う場合と`_`プレースホルダーで値を使わない場合、ユニット値`()`を返して何もしない書き方）
- [x] if let記法（1つのパターンのみ処理したい場合のmatchの糖衣構文、網羅性チェックを失う代わりに簡潔になる、elseとの組み合わせ）
- [x] let-else記法（パターンにマッチしたら値を束縛して処理を続行、マッチしなければelseで早期リターン、「幸せな道」を本流に保てる）
- [x] unwrap（unwrapやunwrap_orなど、unwrap系の主要なメソッドを網羅。どのような場面でunwrapを使うべきかも合わせて記載する。）

## 06-project

The Rust Programming Language 7章の範囲をメインに扱う。複数ファイル構成のコード例は`:::project`記法（1つのCargoプロジェクトとして表示・Playground連携）で記載する。

- [x] パッケージ（1つ以上のクレートをまとめる単位、Cargo.tomlを持つ、ライブラリクレートは最大1つ・バイナリクレートは複数持てる、`cargo new`が生成するもの）
- [x] クレート（コンパイルの最小単位、バイナリクレートとライブラリクレートの2種類、クレートルート（`src/main.rs`・`src/lib.rs`の慣習）、`src/bin/`による複数バイナリクレート）
- [x] モジュール（`mod`キーワードによる定義、モジュールツリー、ネストできる、コードの整理とプライバシー境界という2つの役割、インラインモジュール）
- [x] パス（モジュールツリー内の項目を参照する方法、`crate::`から始まる絶対パスと相対パス、どちらを使うべきかの指針（コードの移動に強いのはどちらか））
- [x] super（親モジュールから始まる相対パス、ファイルシステムの`..`に相当、親と一緒に移動する可能性が高いコードでの使いどころ）
- [x] pubキーワード（Rustはデフォルトですべて非公開、モジュールを`pub`にしても中身は別途`pub`が必要、構造体はフィールドごとに`pub`指定、enumは`pub`でバリアントもすべて公開される）
- [x] use宣言（パスをスコープに持ち込む、useが有効なのは宣言されたスコープ内のみ、関数は親モジュールまで・構造体やenumはフルパスで持ち込む慣習、`as`による別名、ネストしたパス、glob演算子`*`）
- [x] 再エクスポート（`pub use`による再公開、内部のモジュール構造と外部に見せる公開APIを分離できる、使いどころ）
- [x] 外部パッケージの利用（Cargo.tomlの`[dependencies]`への追加、`use`でスコープに持ち込む、`std`は同様に`use`が必要だがdependencies追加は不要）
- [x] モジュールのファイル分割（`mod`宣言によるファイル読み込み、`mod`はincludeではなく宣言は1回だけ、`src/garden.rs`方式と旧スタイルの`src/garden/mod.rs`方式、サブモジュールのディレクトリ配置）
- [x] Cargo（ビルドシステム兼パッケージマネージャという位置づけ（`rustc`直接実行との違い）、代表コマンド（`new`・`build`・`run`・`check`・`test`・`add`）、`Cargo.toml`と`Cargo.lock`の役割分担、crates.ioとの関係。プロファイル・`cargo publish`・featuresは扱わず概観に絞る。作成後に`package`・`crate`・`external-package`のCargo言及をリンク化する）
- [x] ワークスペース（複数のパッケージをまとめて管理する単位、`[workspace]`と`members`、`Cargo.lock`と`target`ディレクトリの共有、メンバー間の依存はパスで指定。TRPL 14章の範囲だがパッケージからのリンク待ちのため本章に置く）

## 07-trait

The Rust Programming Language 10章の範囲をメインに扱う。既存エントリからのリンク待ちが最も多い領域（`trait`は14箇所から参照）で、以降のどの章の説明にも前提として必要になる。

- [x] トレイト（型が持つ振る舞いを定義する仕組み、`trait`宣言と`impl Trait for Type`、他言語のインターフェースとの違い、オーファンルール（コヒーレンス））
- [ ] デフォルト実装（トレイト側に既定の処理を書く、実装側での上書き、デフォルト実装から他のメソッドを呼ぶ）
- [x] ジェネリクス（型引数`<T>`による抽象化、関数・構造体・列挙型・implブロックでの使い方、単相化によって実行時コストが生じないこと）
- [ ] トレイト境界（`T: Trait`で型引数に振る舞いを要求する、`+`による複数指定、`where`句、引数位置の`impl Trait`）
- [ ] impl Trait（戻り値位置で「そのトレイトを実装した何らかの1つの型」を返す、クロージャやイテレータを返す用途、引数位置との意味の違い）
- [ ] トレイトオブジェクト（`dyn Trait`による動的ディスパッチ、ジェネリクス（静的ディスパッチ）との使い分け、オブジェクト安全性）
- [ ] 関連型（トレイトに紐づく型を実装側で決める、ジェネリックな型引数との違い、`Iterator::Item`の例）
- [ ] derive属性（`#[derive(...)]`による標準トレイトの実装の自動生成、導出できるトレイト一覧、全フィールドが実装している必要があること）
- [ ] Debugトレイト（`{:?}`・`{:#?}`での出力、deriveでの導出、開発者向け表示という位置づけ）
- [ ] Displayトレイト（`{}`での出力、deriveできず手動実装が必要な理由、`ToString`が自動で付いてくること）
- [ ] 比較のトレイト（`PartialEq`/`Eq`と`PartialOrd`/`Ord`、部分と全の違い、浮動小数点型が`Eq`を実装しない理由）
- [ ] Defaultトレイト（`Default::default()`と`Type::default()`、構造体更新記法との組み合わせ、deriveでの導出）
- [ ] 演算子オーバーロード（`std::ops`のトレイト（`Add`・`Sub`・`Not`など）を実装して独自の型に演算子を使えるようにする、`&&`・`||`など対応トレイトがなくオーバーロードできない演算子、比較演算子は`PartialEq`/`PartialOrd`が担うこと）
- [ ] ライフタイム（参照が有効であり続ける期間、コンパイラが追跡するもの、ダングリング参照・NLLとの関係）
- [ ] ライフタイム注釈（`'a`の記法、関数シグネチャ・構造体・implブロックでの指定、ライフタイム省略規則、`'static`）

## 08-error

The Rust Programming Language 9章の範囲をメインに扱う。`Option`・`Result`・`unwrap`は05-enumにあるため、本章は「パニックとResultの選択」と「エラーの伝播・変換」に絞る。

- [ ] 回復可能なエラーと回復不能なエラー（`Result`と`panic!`の使い分けの指針、ライブラリとアプリケーションでの判断の違い、プロトタイプやテストでの割り切り）
- [ ] ?演算子（`Err`・`None`のとき即座に呼び出し元へ返す、`From`によるエラー型の自動変換、match入れ子との比較、使える関数の戻り値型の制約（`main`を含む））
- [ ] Errorトレイト（`std::error::Error`、エラー型に期待される性質（`Debug`+`Display`）、`source`によるエラーの連鎖）
- [ ] `Box<dyn Error>`（異なるエラー型をトレイトオブジェクトでまとめる、アプリケーション側で手軽に使える戻り値型、型情報が失われるトレードオフ）
- [ ] 独自エラー型（列挙型で失敗の種類を列挙する、`Display`と`Error`の実装、`From`を実装して`?`と繋ぐ）

## 09-collection

The Rust Programming Language 8章の範囲をメインに扱う。`Vec`・`String`は01-basicにあるため、本章はマップ・セットなど残りのコレクションを扱う。

- [ ] コレクション（標準ライブラリが提供するコレクション型の概観、ヒープに置かれ実行時に伸縮すること、用途別の選び方）
- [ ] HashMap（キーと値の対応づけ、`insert`・`get`、所有権の移動、`entry`APIによる「なければ挿入」、反復順序が保証されないこと）
- [ ] HashSet（重複を許さない値の集合、和・積・差の集合演算、`HashMap`との関係）
- [ ] BTreeMap・BTreeSet（キーの順序を保って保持する、`HashMap`・`HashSet`との使い分け（順序・計算量・`Ord`要求））
- [ ] VecDeque（両端キュー、`push_front`・`push_back`、`Vec`との違いと使いどころ）

## 10-test

The Rust Programming Language 11章の範囲をメインに扱う。学習本（`rust-learning`）が第4章から「テスト」を判定方式として使うため、リンク先として早めに必要になる。

- [ ] テスト関数（`#[test]`属性を付けた関数、`cargo test`での実行、パニックしなければ成功という判定方式）
- [ ] assertマクロ（`assert!`・`assert_eq!`・`assert_ne!`、失敗時に表示される値、追加メッセージの指定、比較には`PartialEq`+`Debug`が必要）
- [ ] should_panic属性（パニックすることを期待するテスト、`expected`によるメッセージの絞り込み、範囲が広くなりがちな注意点）
- [ ] Resultを返すテスト（`Result<(), E>`を返して`?`を使う、`should_panic`と併用できないこと）
- [ ] テストモジュール（`#[cfg(test)] mod tests`、テスト時のみコンパイルされる、`use super::*`、非公開の項目もテストできる）
- [ ] 単体テストと結合テスト（同一ファイル内に置く単体テストと`tests/`ディレクトリに置く結合テスト、結合テストは公開APIしか触れない、`tests/common/mod.rs`による共通処理）
- [ ] テストの実行制御（名前でのフィルタ、`#[ignore]`と`--ignored`、既定の並列実行と`--test-threads`、出力を表示する`--show-output`）
- [ ] ドキュメンテーションテスト（`///`のコード例が`cargo test`で実行される、例が壊れないことを保証する仕組み、`no_run`などの属性）

## 11-closure-iterator

The Rust Programming Language 13章の範囲をメインに扱う。

- [ ] クロージャ（`|引数| 式`の記法、環境をキャプチャできる無名関数、型注釈を省略できる理由（1つの呼び出し方に型が固定される）、関数との違い）
- [ ] クロージャのキャプチャ（共有借用・排他借用・ムーブの3通りをコンパイラが選ぶ、`move`キーワードで所有権を奪う、スレッドや戻り値での使いどころ）
- [ ] Fnトレイト（`FnOnce`・`FnMut`・`Fn`の3種類と包含関係、キャプチャの使われ方で決まること、引数としてクロージャを受け取る書き方）
- [ ] 関数ポインタ（`fn`型、クロージャとの違い、3つのFnトレイトすべてを実装すること、`map(Shoe::new)`のような渡し方）
- [ ] イテレータ（要素を順に取り出す仕組み、遅延評価で呼ばれるまで何もしない、`iter`・`iter_mut`・`into_iter`の3通り、for式との関係）
- [ ] Iteratorトレイト（`Item`関連型と`next`だけを実装すればよいこと、自作イテレータ、`next`は`Option<Item>`を返す）
- [ ] イテレータアダプタ（`map`・`filter`・`enumerate`・`zip`・`rev`・`take`・`skip`・`chain`、消費しないと何も起きない警告）
- [ ] 消費アダプタ（`sum`・`count`・`fold`・`any`・`all`・`find`・`for_each`、イテレータの所有権を取ること）
- [ ] collect（イテレータをコレクションに集める、型注釈が必要な理由、`FromIterator`、`Result`の並びを`Result<Vec<_>, _>`に畳み込む使い方）

## 12-smart-pointer

The Rust Programming Language 15章の範囲をメインに扱う。所有権・借用の理解が前提になるため、03-ownershipと07-traitの後に置く。

- [ ] スマートポインタ（ポインタに所有権や付加情報を持たせた型の総称、`Deref`と`Drop`を実装すること、`String`や`Vec`も該当すること、参照との違い）
- [ ] Box（値をヒープに置く最も単純なスマートポインタ、使いどころ3つ（コンパイル時にサイズが決まらない型・大きなデータのムーブ回避・トレイトオブジェクト）、再帰的なデータ構造）
- [ ] Derefトレイト（`*`演算子の挙動を定義する、参照外し型強制（deref coercion）で`&Box<T>`が`&T`として渡せる仕組み、`DerefMut`）
- [ ] Dropトレイト（値が破棄されるときの後始末、スコープ終端で宣言の逆順に呼ばれること、手動呼び出しは不可で`std::mem::drop`を使うこと）
- [ ] Rc（参照カウントによる複数所有、`Rc::clone`はカウントを増やすだけで深い複製ではないこと、共有は不変のみ、シングルスレッド専用（`Arc`との対比））
- [ ] RefCell（借用規則をコンパイル時ではなく実行時に検査する、`borrow`・`borrow_mut`、違反するとパニック、`Cell`との違い）
- [ ] 内部可変性（不変な参照越しに中身を変更できる仕組み、なぜ健全なのか、`Cell`・`RefCell`・`Mutex`という選択肢、`Rc<RefCell<T>>`の組み合わせ）
- [ ] 循環参照とWeak（`Rc`同士が参照し合うとカウントが0にならずリークすること、`Weak`と`upgrade`による解決、`strong_count`と`weak_count`）
