## 指摘一覧

### 要修正

なし。

### 推奨

1. **`import.meta.main` の Node バージョン要件が明文化されていない**（`scripts/sync-playground-gists.mjs:296`）
   `import.meta.main` は Node 24.2 で追加された機能で、それ未満の Node では `undefined`（falsy）になり `main()` が実行されず **exit 0 で黙って何もしない**。現環境（v25.9.0）では動作確認済みだが、この失敗モードは静かで気づきにくい（Gist が作られないままビルドの R-7(e) 検証で初めて発覚する）。`package.json` に `engines.node` を明記するか、実行前提を implementation-rules 1章の `sync:playground` 行に一言添えることを推奨。実データでの初回実行は PG1-4 のため、その前に対応すれば十分。

### 軽微

1. **spec R-1 の追記が feat コミットに同乗し、コミットメッセージにも記載がない**（`e0f8921` の `docs/spec/playground-project.md`）
   「ファイルは直下のコードブロックのみ」の R-1 追記は仕様変更であり、先行の docs コミット `c3159d3` に含めるのが仕様駆動の建付けとして一貫する。`e0f8921` のメッセージ本文は plugins / scripts / package.json のみ列挙しており spec 変更に触れていない。実害はなく、計画の実施履歴には正しく記録されている。
2. **`readGistMap` が JSON.parse 結果を無検証で `GistMap` にキャストしている**（`plugins/project-gist.mjs:66-73`）
   有効な JSON だが形状が違う場合（配列・値が文字列等）に黙って進み、後段で不可解に壊れる。手書きしないファイルなので実運用リスクは低いが、PG1-3 でビルド側からも読む共有関数になるため、そのタイミングで最低限の形状ガード（オブジェクトであること・`id` が文字列であること）を検討するとよい。
3. **`--verify` とファイル引数の併用時、引数が黙って無視される**（`scripts/sync-playground-gists.mjs:275-295`）
   R-10 上 `--verify` は全エントリ確認なので挙動自体は正しいが、`npm run sync:playground -- a.md --verify` と打った利用者には引数が効いていないことが伝わらない。併用時に一言注意を出すと親切。
4. **入れ子ディレクティブ内の `:::project` の扱いが spec 未定義**（`scripts/sync-playground-gists.mjs:63-70`）
   `findProjects` は `::::details` 等の中にある `:::project` も走査対象に含める（直下のコードブロックのみをファイルとする R-1 とは別の論点）。spec はこのケースを定義していないため、PG1-3 のビルド側プラグインと扱いがずれないよう、PG1-3 実装時に確認・必要なら spec に明記するとよい（R-8 但し書きの「双方を同時に直す」対象に含まれる話）。

## 総合判定

**承認**（要修正なし）。推奨・軽微指摘は任意対応でよく、推奨1は PG1-4 の初回実運用まで、軽微2・4 は PG1-3 実装時の対応で足りる。
