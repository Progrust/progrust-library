**借用チェッカー**（borrow checker）は、[[ownership]]の移動・[[borrow]]の規則・ライフタイム<!-- TODO: [[lifetime]] 作成後にリンク -->が守られているかを**コンパイル時に**検査するRustコンパイラの機構です。違反したコードはコンパイルエラーとなり、実行ファイルになりません。

借用チェッカーが弾くのは、他の言語であれば実行時の不具合（解放済みメモリへのアクセス・二重解放・データ競合）として現れる問題です。検査はコンパイル時に完結するため、この安全性のために実行時のコストが増えることはありません。

<!-- rustc: expect E0502 -->
```rust playground
fn main() {
    let mut items = vec!["牛乳", "卵"];

    let first = &items[0]; // items を共有借用
    items.push("パン");    // エラー: E0502（共有借用が生きている間に排他借用はできない）

    println!("最初の商品: {first}"); // ここで first を使うため、共有借用がまだ続いている
}
```

## 何を検査するのか

借用チェッカーの検査は大きく3つに分けられます。右列は違反したときに出る代表的なエラーコードです。

| 検査項目 | 内容 | エラーコード |
| --- | --- | --- |
| 初期化と移動 | [[move]]済み・未初期化の値を使っていないか | E0382 |
| 借用規則 | 共有借用と排他借用が共存していないか | E0502 |
| 借用規則 | 排他借用が同時に2つ以上ないか | E0499 |
| ライフタイム | 関数のローカルな値への[[reference]]を返していないか（[[dangling-reference]]） | E0515 |

:::message{tip}
エラーコードは`rustc --explain E0502`のようにコマンドで詳しい解説を読めます。
:::

:::details[E0382・E0499・E0515 のコード例]

**E0382**（ムーブ済みの値の使用）— 所有権が移った後の[[variable]]は使えません。

<!-- rustc: expect E0382 -->
```rust playground
fn archive(receipt: String) {
    println!("保管しました: {receipt}");
} // ここで receipt は破棄される

fn main() {
    let receipt = String::from("レシート: 牛乳 200円");
    archive(receipt); // 引数への受け渡しで所有権がムーブする

    println!("{receipt}"); // エラー: E0382（ムーブ済みの値を使っている）
}
```

**E0499**（排他借用の重複）— 同じ値への排他借用は同時に1つまでです。

<!-- rustc: expect E0499 -->
```rust playground
fn main() {
    let mut balance = 1000;

    let from_atm = &mut balance;
    let from_app = &mut balance; // エラー: E0499（2つ目の排他借用）

    *from_atm += 500;
    *from_app -= 300;
    println!("残高: {balance}円");
}
```

ATMとアプリの両方から同時に残高を書き換えられない、というイメージです。

**E0515**（ローカル変数への参照を返す）— 関数を抜けると破棄される値の参照は返せません（[[dangling-reference]]）。

<!-- rustc: expect E0515 -->
```rust playground
fn label() -> &'static str {
    let text = String::from("特売品");
    &text // エラー: E0515（ローカル変数 text への参照を返そうとしている）
} // ここで text は破棄される

fn main() {
    println!("{}", label());
}
```

:::

## 実行時コストがかからない理由

借用チェッカーの検査はコンパイル時にすべて終わり、生成される機械語には借用の状態を追跡するコードが一切含まれません。サイズの決まった型`T`への参照`&T`・`&mut T`は、実行時にはC言語のポインタと同じ「アドレスだけの値」であり、参照カウントやロックのような付随データを持ちません（`&str`や`&[T]`のようにサイズが実行時に決まる型への参照だけは、長さの情報も併せ持ちます）。

つまり借用チェッカーは、「安全性」と「速度」のどちらかを諦めるという従来の二択を、検査をコンパイル時へ前倒しすることで回避しています。

## 補足

:::details[GC・参照カウントとの比較]

| 方式 | 検査のタイミング | 実行時の負担 |
| --- | --- | --- |
| 借用チェッカー（Rust） | コンパイル時 | なし（検査コードは生成されない） |
| GC（Java・Goなど） | 実行時 | 到達可能性の走査・回収の一時停止 |
| 参照カウント（Swiftなど） | 実行時 | 参照の増減ごとにカウンタ更新 |

ただしRustにも、`Rc`のように参照カウントで所有権を共有する型や、`RefCell`のように借用規則を実行時に検査する型があります<!-- TODO: [[rc]] 作成後にリンク -->。これらは借用チェッカーだけでは表現できない共有が必要な場面で明示的に選ぶものであり、既定で実行時コストがかかるわけではありません。
:::

:::details[unsafeでも借用チェッカーは止まらない]
`unsafe`ブロックは借用チェッカーを無効化しません。`unsafe`が追加で許可するのは生ポインタの[[dereference]]や`unsafe fn`の呼び出しなどに限られ、`unsafe`ブロック内に書いた通常の参照も変わらず検査されます。

ただし生ポインタ（`*const T` / `*mut T`）自体は借用チェッカーの追跡対象外です。そのため生ポインタを使う場合は、安全性の担保がコンパイラから**プログラマの責任へ移る**ことになります。
:::

:::details[検査はMIR上で行われる]
借用チェックは、コンパイラが内部で使う中間表現MIR（Mid-level Intermediate Representation）の制御フローグラフ上で行われます。[[non-lexical-lifetimes]]が借用の有効範囲を字句上の[[scope]]から切り離せるのも、この解析がMIRの制御フローに基づいているためです。

```mermaid
graph LR
  A[ソースコード] --> B[型検査]
  B --> C[MIRの生成]
  C --> D[借用チェック]
  D -->|OK| E[機械語の生成]
  D -->|違反| F[コンパイルエラー]
```
:::

:::details[安全なコードでも弾かれることがある]
借用チェッカーは保守的で、「安全だと証明できたものだけを通す」という方針で動きます。そのため実際には安全なコードであっても、証明できなければ拒否されます。

たとえば以下は、`first`と`second`が配列の異なる要素を指すことが人間には分かります。しかし借用チェッカーは[[array-type]]の要素を添字ごとに区別せず、ひとまとめの`scores[_]`として扱うため、同じ場所への排他借用が2つあると判断します。

<!-- rustc: expect E0499 -->
```rust playground
fn main() {
    let mut scores = [80, 95, 70];

    let first = &mut scores[0];
    let second = &mut scores[1]; // エラー: E0499（別の要素だが区別されない）

    *first += 5;
    *second += 5;
    println!("{scores:?}");
}
```

こうした場合は`split_at_mut`や`get_disjoint_mut`のような[[standard-library]]のAPIを使うと、安全なまま目的を達成できます。判定の精度自体もコンパイラの改良とともに向上しており、[[non-lexical-lifetimes]]の導入はその代表例です。
:::
